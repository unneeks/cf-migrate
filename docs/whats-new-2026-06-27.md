# What's new — 2026-06-27

Changes to the Map Run Diff Viewer (`packages/extension/src/webviews/MapRunDiffPanel.ts`) made today.

## Full source rendering

The CF and GHA panes now reliably show the entire source file, not just the mapped step
snippets. (The earlier report of truncation turned out to be a stale installed `.vsix` —
see "Panel re-render on reopen" below for the related fix.)

## Pipeline context sections

Each pane now has a section above the code, parsed directly from the source files
(`source_file` / `target_workflow`), not from `map.json`:

- **Codefresh pane** — Triggers, Contexts, and Variables (`cf_export`'d vars, `spec.variables`,
  and referenced `${{VAR}}` context vars, excluding built-in `CF_*` runtime vars).
- **GitHub Actions pane** — Triggers (`on:` block), Environment (`env:` block), and Secrets &
  Vars. Rows are rendered in the same order as the CF side so each variable lines up with its
  `secrets.X` / `vars.X` / `env.X` reference, with a mapped/missing badge on each side.

Both sections are collapsible.

## Connector line fix

The SVG lines linking a CF step to its GHA step previously required both step blocks to be
simultaneously visible in the viewport — since the two panes scroll independently and steps
rarely span the same number of lines on both sides, the lines almost never showed. Now a
connector renders as soon as *either* side is visible, clamping the off-screen endpoint to the
nearest pane edge (dimmed) so it always points toward the other step.

## Steps collapsed by default

Step blocks now render collapsed (title bar only) instead of expanded, matching how most users
scan the diff — expand a step on click as before.

## Auto-scroll alignment

Scrolling the Codefresh (left) pane now auto-scrolls the GitHub Actions (right) pane so the
step at the top of the CF viewport aligns to the same position on the GHA side. Driven
one-directionally from left to right to avoid a scroll feedback loop.

## Editable GHA pane

The GHA pane can now be edited directly. **Edit** swaps the rendered view for a plain textarea;
**Save** writes the new content straight back to `meta.target_workflow` on disk and re-renders
the panel from the updated file.

## Learn Rule from manual edits

Every save is recorded as a before/after snapshot in a sidecar file next to the map run
(`<name>.edits.json`), scoped to whichever step was selected at save time. A new
**🧠 Learn Rule** button (enabled once an edit exists) sends the earlier machine-generated
mapping plus the before/after snippets to the LLM, asking it to generalise the fix into a
reusable rule (new `LearnedRuleSchema` Zod gate, new `rule-learning` prompt phase). The
validated response is:

- Appended to whatever rules YAML the map run's `meta.mapping_source` points to (created if
  missing).
- Added to the knowledge base as a new `pattern` item via the existing `KBManagerAgent.create()`
  facade — so it's indexed in `manifest.json` and picked up by future KB searches.

## Panel re-render on reopen

`MapRunDiffPanel.show()` previously just called `.reveal()` on an already-open panel without
re-rendering it — so a panel left open from earlier kept showing whatever it had at creation
time, indistinguishable from a rendering regression until the whole window was reloaded.
Reopening a panel now always re-renders against the current files and code.

## Learn Rule: Copilot-only + model selection

Learn Rule now explicitly checks `services.llmAvailable` and refuses with a clear message if
Copilot Chat isn't available — it never falls back to a deterministic/other provider. New
setting `cfMigrate.learnRuleModel` (default empty = let the provider pick its own
best-available model, the closest proxy for "Copilot Chat's default" since VS Code doesn't
expose the chat panel's active model to extensions). New command **CF Migrate: Select Learn
Rule Model** opens a QuickPick of your actually-available Copilot models and saves the choice.

## Analyse/Plan result caching

New `packages/extension/src/services/AnalysisPlanCache.ts`: results are cached at
`.cf-migrate/analysis-plan-cache.json`, keyed by a content hash of the pipeline's raw YAML
(plan additionally keyed by a hash of the analysis it was built from). `cf-migrate.analyse` /
`cf-migrate.plan` reuse the cached result instead of calling the LLM again when nothing
changed; new **`cf-migrate.analyse.force`** / **`cf-migrate.plan.force`** commands bypass the
cache.

## Template/instance detection & reusable-workflow generation

See `docs/template-instance-reusable-workflow-spec.md` for the full spec. Summary: pipelines
sharing an identical mapping structure (read from existing `*.map.json` data — same step
sequence, same rules, same `mapping_source`) are now grouped in the Map Run tree as
`Template: <name>` with instance children, instead of each appearing as a flat independent
entry. A new **Generate Caller Workflows** command (on the template-group node) declares a
`workflow_call` trigger on the template's suggested workflow and writes one thin caller
workflow per instance, each passing that instance's own CF variable values as `with:` inputs.

## KB frontmatter bugfix

`kb-default/patterns/hooks-to-always-steps.md` had an unquoted `description:` field
containing a literal `` `if:` `` — unsafe YAML that threw "Nested mappings are not allowed in
compact mappings" whenever the KB manifest was rebuilt (Learn Rule's `kbManager.create()` call
does this). Fixed by quoting the value; this was a pre-existing landmine in the seed KB data,
not something introduced today.

## Tests

Added `vitest` to `packages/extension` (`npm test`) with unit tests for the two new pure-logic
modules: `TemplateGrouping.test.ts` and `ReusableCallerGenerator.test.ts` — including
regression tests for bugs found during manual verification (a name collision that silently
overwrote one variable's value; naming inconsistency across multiple instances). See
`docs/test-plan-2026-06-27.md` for the full automated + manual test plan.
