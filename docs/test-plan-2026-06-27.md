# Test plan — 2026-06-27 changes

Covers everything touched today across the Map Run viewer, the LLM-driven commands, and the
new template/instance reusable-workflow feature. Automated coverage exists where the logic is
pure (no `vscode` API); everything else is a manual VS Code verification checklist.

## Automated tests

```
cd packages/extension && npm test
```

- `src/utils/TemplateGrouping.test.ts` — 5 tests: groups identical-structure pipelines,
  rejects structurally-different ones, rejects same-steps-different-`mapping_source`, a lone
  match stays standalone (not a 1-entry group), 3+-way groups put every match but the
  template into `instances`.
- `src/generation/ReusableCallerGenerator.test.ts` — 13 tests: clean variable names from
  structured fields, disambiguation of same-named fields under different steps (the
  staging/production `replicaCount` collision), the regression where a name collision
  silently overwrote one variable's value, identity-field exclusion (`metadata.name`/
  `project`), naming consistency across multiple instances, `workflow_call` insertion +
  idempotency + no-op-when-no-`on:`-block, and caller-workflow shape.

Run `npx vitest run` for a single pass, or `npx vitest` to watch.

## Manual verification (VS Code extension host)

For all of these: `npm run build` in the repo root, then `cd packages/extension && npx vsce
package --no-dependencies --allow-missing-repository && code --install-extension
cf-migrate-vscode-0.1.0.vsix`, then reload the window before testing (see "Panel re-render on
reopen" below for the one case that no longer requires a full reload).

### Map Run viewer — full source rendering
1. Open the Map Run tree, open `PROD/crm-deployment`.
2. **Expect:** both panes render the entire source file (scroll to the bottom of each — the
   CF pane should reach `notify_teams`, the GHA pane should reach the `notify` job), not just
   the mapped step snippets.

### Pipeline context sections
1. With the same map run open, check both panes above the code area.
2. **Expect:** CF pane shows Triggers / Contexts / Variables sections; GHA pane shows
   Triggers / Environment / Secrets & Vars. Variable rows line up in the same order on both
   sides with mapped/unmapped badges (e.g. `SONAR_TOKEN` → `secrets.SONAR_TOKEN`).
3. Click the collapse chevron on either section. **Expect:** it collapses without affecting
   the other pane.

### Connector lines
1. Scroll the CF pane up and down while watching the GHA pane (don't scroll it manually).
2. **Expect:** connector lines stay visible (dimmed when the GHA side is off-screen) instead
   of disappearing — this was the original "lines only appear when scrolled to align" bug.

### Steps collapsed by default / auto-scroll alignment
1. Reopen the map run fresh. **Expect:** every step renders collapsed (title bar only).
2. Click a step to expand it, then scroll the CF pane. **Expect:** the GHA pane auto-scrolls
   so the step at the top of the CF view aligns to the same position on the GHA side.
3. Scroll the **GHA** pane manually. **Expect:** the CF pane does NOT move (one-directional
   sync only — no feedback loop).

### Editable GHA pane + manual-edit tracking
1. Click **✎ Edit** on the GHA pane, change a line, click **Save**.
2. **Expect:** the actual `target_workflow` file on disk is updated, and the panel re-renders
   from the new content.
3. Check `<map-run-name>.edits.json` next to the `.map.json` file. **Expect:** a new record
   with `before`/`after` snippets and (if a step was selected before editing) the `seq`.

### Learn Rule
1. After saving an edit, click **🧠 Learn Rule** (should now be enabled).
2. **Expect:** a progress notification, then a success message naming the new `rule_id` and
   the KB item id.
3. Check `meta.mapping_source` path (e.g. `mapping_data/cf_gha_mappings.yaml`) — **expect** a
   new entry appended.
4. Check `kb-default/patterns/` — **expect** a new `.md` file, and that
   `kb-default/manifest.json` was rebuilt to include it.
5. Disable/uninstall Copilot Chat (or check with it unavailable) and retry. **Expect:** a
   clear error ("Learn Rule requires GitHub Copilot Chat…"), no silent fallback to any other
   provider.

### Learn Rule model selection
1. Run **CF Migrate: Select Learn Rule Model** from the Command Palette.
2. **Expect:** a QuickPick listing your available Copilot models plus a "Default" option.
3. Pick a specific model, then run Learn Rule again. **Expect:** `cfMigrate.learnRuleModel`
   in settings reflects your choice, and the ledger's `llm.call` entry for that run shows the
   corresponding model.

### Analyse/Plan caching
1. Run **CF Migrate: Analyse Active Pipeline**, note the constructs count.
2. Run it again immediately. **Expect:** an info message saying it's using the cached result
   from <timestamp>, no new LLM call (no progress notification spinner).
3. Run **CF Migrate: Force Re-analyse (ignore cache)**. **Expect:** it actually re-runs.
4. Edit the active pipeline's YAML (any whitespace change), run Analyse again. **Expect:** it
   re-runs automatically (content hash changed) without needing Force.
5. Repeat 1–4 for Plan / Force Re-plan, confirming Plan's cache also invalidates when the
   underlying Analysis result changes even if the pipeline file didn't.
6. Check `.cf-migrate/analysis-plan-cache.json` exists and is git-ignored.

### Template/instance detection & tree hierarchy
1. Refresh the Map Run tree (`testdata/artifacts/mapperruns/` now has
   `BILLING_billing-deployment`, `NOTIFICATIONS_notifications-deployment`, and
   `PROD_crm-deployment` map runs, all sharing one mapping structure).
2. **Expect:** a single `Template: billing-deployment` node at the tree root (not nested
   under a project), expandable to show the template entry plus two instance children
   labelled `BILLING/billing-deployment (template)`, `NOTIFICATIONS/notifications-deployment
   · instance`, `PROD/crm-deployment · instance`.
3. Click the template entry. **Expect:** the normal Map Run diff panel opens.
4. Click an instance entry. **Expect:** an info message pointing back to the template, with
   an "Open Template Map Run" action.

### Generate Caller Workflows
1. Right-click (or use the inline icon on) the `Template: billing-deployment` group node, run
   **Generate Caller Workflows**.
2. **Expect:** a success message reporting N inputs added to the template workflow and 2
   caller files written.
3. Open `BILLING_billing-deployment.suggested.yml`. **Expect:** a new `workflow_call:` block
   under `on:` with one input per detected variable (`ECR_REPO`, `HELM_RELEASE_NAME`,
   `image_name`, `deploy_to_staging_chart_name`, `deploy_to_production_chart_name`, etc.) —
   the rest of the file (jobs/steps/comments) byte-for-byte unchanged below the `on:` block.
4. Open the two generated `*.caller.yml` files. **Expect:** each has `uses:
   ./BILLING_billing-deployment.suggested.yml` and a `with:` block populated with *that
   instance's own* values (e.g. notifications-app's caller has
   `replicaCount`-equivalents `1`/`3`, not billing's `3`/`6`).
5. Run **Generate Caller Workflows** again. **Expect:** the success message says the
   template already had a `workflow_call` trigger ("left it as-is") — no duplicate trigger
   block, callers rewritten with the same content (idempotent).

### Panel re-render on reopen (regression fix)
1. Open a map run, leave the panel open, then have its `target_workflow` file change on disk
   (e.g. via Generate Caller Workflows touching the template, or just hand-edit it).
2. Reopen the same map run from the tree (don't reload the window).
3. **Expect:** the panel reflects the new file content — previously it just called `.reveal()`
   on the existing panel without re-rendering, so stale content looked identical to a
   rendering bug.

### KB frontmatter fix
1. Trigger any KB list/manifest rebuild (e.g. run Learn Rule once, or open the Knowledge Base
   view).
2. **Expect:** no "Nested mappings are not allowed in compact mappings" error. (Root cause:
   `kb-default/patterns/hooks-to-always-steps.md` had an unquoted `description:` containing a
   literal `` `if:` `` — fixed by quoting the whole value.)
